# Автоматические коммиты и релизы

Настроено 6 ноября 2026 года по прямому запросу владельца. Коммерческие ворота
не меняются; эта настройка публикует существующее приложение.

На этом Mac глобальный `~/.codex/hooks.json` вызывает
`~/.codex/hooks/ensure_remote_sync.py` на событии Stop. Обработчик коммитит только
изменения текущего запроса относительно сохранённого baseline. Чужие изменения,
секреты и игнорируемые сборки не включаются. При расхождении с upstream обработчик
возвращает задачу агенту для безопасной синхронизации и push, без force.

После синхронизации обработчик читает **закоммиченный** `.codex/release.json`.
В ветке `main` он извлекает коммит через `git archive` во временную папку и
запускает `python3 scripts/release.py`. Грязное рабочее дерево не попадает в релиз.
Отдельный локальный Stop-хук не нужен: несколько обработчиков одного события
Codex запускает параллельно, а не последовательно. На другом Mac нужны эти
глобальные обработчики и доверие к ним в Settings → Hooks.
Механизм источников и доверия описан в [OpenAI Docs](https://learn.chatgpt.com/docs/hooks).

## Проверки и публикация

1. Проверить, что исходный коммит всё ещё является HEAD синхронизированной `main`.
2. Выполнить `make verify`: коммерческий валидатор, тесты безопасности релиза,
   `swift test --package-path DiskLens`, `swift build --package-path DiskLens -c release`.
3. Собрать универсальный `.app` штатным `DiskLens/scripts/build-app.sh` в пустую
   папку. Для SwiftPM и FSEvents нужен обычный локальный процесс вне песочницы агента.
4. Упаковать ZIP, распаковать именно этот архив, проверить подпись, plist,
   `arm64` и `x86_64`. Запустить распакованное приложение с отдельной историей
   и одним временным файлом; дождаться сохранённого полного замера без ошибок.
   Проверочная копия завершает только собственный процесс приложения.
5. Ещё раз проверить синхронизацию. Создать новый тег на проверенном коммите,
   затем черновик GitHub Release. Загрузить ZIP, `RELEASE.json` и `SHA256SUMS.txt`,
   сверить размеры и серверные SHA-256. Опубликовать preview только после успеха.

Публикация помечена как prerelease. Исходная версия в
`DiskLens/assets/Info.plist` задаёт нижнюю границу, сейчас `0.2.0`.
Если версия уже занята, скрипт увеличивает patch наибольшего существующего
семантического тега. Версия записывается в plist только временной копии для
упаковки; коммит не меняется. Повтор того же коммита проверяет существующий
релиз и завершается без новой сборки. Существующие теги и опубликованные
выпуски не перезаписываются. Черновик того же коммита можно дозагрузить заново.

Страница загрузки закреплена за конкретным проверенным preview. Автоматические
следующие patch-релизы доступны в GitHub Releases; обновление закреплённой
версии на сайте выполняется вместе со ссылками и текстом установки по
`docs/GITHUB-PAGES.md`. GitHub `releases/latest/download` пропускает prerelease.

Ограничения проверки: запуск выполняется на архитектуре текущего Mac.
Наличие Intel-бинарника не подтверждает запуск на Intel. Opt-in тест настоящей
Корзины по умолчанию пропущен. Developer ID и notarization не подтверждаются;
по умолчанию используется ad-hoc подпись. Переменная `DISKLENS_SIGNING_IDENTITY`
может выбрать сертификат из Связки ключей; локальный `.swiftpm/signing-identity`
не входит в архив исходников Stop-хука. ИИ и удаление пользовательских файлов
в релизной проверке не вызываются.

## Доступ и восстановление

Проверка без публикации:

```sh
python3 scripts/release.py --check
make verify
```

GitHub-клиент использует `GH_TOKEN`, затем `GITHUB_TOKEN`, затем Git credential
helper. Нужны права записи в репозиторий. Секреты не передаются аргументами,
не сохраняются скриптом и не выводятся. Xcode Command Line Tools или Xcode,
Swift 5.9+, Git, Python 3.11+ и графическая сессия macOS обязательны.
`scripts/github_release.py` перенесён из навыка
`publish-github-release` и использует только стандартную библиотеку Python.

Лог Stop-релиза хранится локально в `~/.codex/hooks/state/release-logs/`.
При ошибке проверки или загрузки опубликованный релиз не создаётся;
может остаться тег или черновик. Исправить причину и завершить следующую задачу
в `main`. Если требуется повторить тот же коммит в том же запросе, глобальный
обработчик поддерживает `CODEX_HOOK_RETRY_RELEASE=1`; без этого повторный
неуспешный build в одном запросе подавляется. Сам `release.py` отказывается
публиковать из рабочего дерева: нужны переменные `CODEX_RELEASE_SOURCE_REPO`
и `CODEX_RELEASE_COMMIT`, которые передаёт глобальный обработчик.

На запросах без изменений глобальный Stop-хук не создаёт пустой коммит
и не запускает релиз. Явный запрет владельца на коммит или релиз учитывается
глобальным обработчиком для текущего запроса.
