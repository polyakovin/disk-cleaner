# Отчёт о месте на диске

Выясни, что занимает место на диске, и объясни результат на русском языке, если пользователь не запросил другой язык. Замеряй текущую машину и запрошенный том. Не подставляй цифры, имя пользователя или пути из примера.

## Границы задачи

- Запрос отчёта разрешает диагностику. Не удаляй файлы, кэши, снимки, приложения, контейнеры или историю чатов. Не очищай корзину и не запускай команды очистки.
- Пользуйся только метаданными файлов: размером, путём, типом и временем изменения при необходимости. Не открывай содержимое документов, переписки, конфигураций с секретами или баз данных.
- Не устанавливай программы и не обходи ограничения доступа. Если обычного доступа недостаточно, используй штатный механизм разрешений инструмента для конкретной команды чтения. При отказе продолжи доступные замеры и назови ограничение.
- Промежуточные результаты сохраняй в разрешённой рабочей папке, только если это помогает избежать потери вывода. Для обычного отчёта достаточно ответа в чате.

## Сначала установи ёмкость и цель замера

Определи ОС и домашнюю папку средствами среды выполнения. Если пользователь указал конкретный диск или каталог, начинай с него. В остальных случаях измерь основной том и домашнюю папку.

На macOS:

```sh
df -k / /System/Volumes/Data
diskutil apfs list
tmutil listlocalsnapshots /
```

При необходимости уточни снимки именно целевого тома командой `diskutil apfs listSnapshots /System/Volumes/Data`. Это команды чтения. Ошибка `DiskManagement framework` в песочнице не означает поломку диска. Получи разрешение на конкретную команду чтения через инструмент либо укажи, что структуру APFS проверить не удалось.

Для APFS используй поля `Capacity Ceiling`, `Capacity In Use By Volumes` и `Capacity Not Allocated` из контейнера, к которому относится целевой том. Системный том, Data, VM и Preboot делят место контейнера. Не складывай ёмкость строк `df`. Если `diskutil` недоступен, сообщи свободное место и заполненность тома Data по `df`, не выдавая их за точный итог всего контейнера.

На Linux достаточно `df -k` для нужных точек монтирования. Не складывай повторные строки одного устройства, bind mounts или вложенные тома. На другой ОС сообщи, что помощник не поддерживает её, и выбери доступный штатный инструмент чтения.

## Найди основные потребители

Для измерения каталогов используй [scripts/scan_sizes.py](scripts/scan_sizes.py). Он вызывает системный `du`, ограничивает время работы, агрегирует ошибки доступа и выводит JSON с размерами в байтах. Требуется Python 3, сторонних библиотек нет.

```sh
python3 <skill-dir>/scripts/scan_sizes.py --depth 1 --top 20 --timeout 180 "$HOME"
python3 <skill-dir>/scripts/scan_sizes.py --depth 1 --top 15 --timeout 180 /Applications /Library /opt /private
```

Подставь действительный путь к папке скилла. Второй пример относится к macOS: выбирай существующие каталоги на целевом томе. На Linux можно начать с `du -x -k --max-depth=1` в корне целевого тома; затем изучить крупные ветви, используя помощник.

Не запускай одновременно обход домашней папки и полный обход тома, включающий эту папку. Независимые непересекающиеся ветви можно измерять параллельно, когда это ускоряет работу. Не повторяй уже завершённые замеры без причины. При долгом сканировании запускай команду с возвратом управления и кратко сообщай о найденном и оставшихся проверках.

Спускайся на один-два уровня в самые большие ветви, пока названия в отчёте не станут понятными: приложения, музыка, локальная копия облачного диска, игры, проекты, кэши, SDK или данные ИИ-инструмента. Ориентируйся на измеренные размеры, а не на заранее заданный список.

На macOS часто полезно уточнить:

- `~/Library/Application Support`, `~/Library/Caches`, `~/Library/Containers`, `~/Library/Developer`;
- `~/.npm`, `~/.cache`, `~/.gradle`, `~/.codex` и каталоги проектов, если они велики;
- Documents, Music, Movies, Downloads и локальные папки облачной синхронизации.

Скрытые папки учитываются. `du -x` не переходит на другие файловые системы; содержимое отдельных смонтированных томов оценивай отдельно. Не скачивай облачные файлы ради замера.

Если общий размер каталога значительно больше показанных подпапок, проверь файлы непосредственно в нём:

```sh
python3 <skill-dir>/scripts/scan_sizes.py --files --top 10 "$HOME/.codex"
```

Этот режим читает только метаданные файлов верхнего уровня, включая SQLite и журналы. Он не открывает базы и не просматривает сообщения.

## Проверь трактовку цифр

- Вывод `du -k` и `df -k` содержит КиБ. Переводи в байты умножением на 1024. Для пользовательского отчёта используй десятичные ГБ: байты / 1 000 000 000. ГиБ используй только с явным обозначением и последовательно во всём отчёте.
- Общий размер папки включает её подпапки. В основном списке показывай непересекающиеся категории. Дочерние размеры добавляй как пояснение: «Codex: 33 ГБ, из них история сессий: 22 ГБ». Не складывай родителя с потомком.
- Складывай кандидатов на очистку только при отсутствии пересечения путей. Кэш внутри CapCut учитывай отдельно от родительской папки Movies только при подсчёте кандидатов, где родителя нет.
- `total_bytes: null`, `status: partial`, `status: timed_out` и ошибки доступа означают неполный замер. Не трактуй отсутствующий размер как ноль. Найденные размеры можно привести с указанием ограничения.
- `du` показывает выделенные файловые блоки, а не гарантированно освобождаемые уникальные блоки. APFS-клоны, hard links, snapshots, сжатие и защищённые каталоги могут дать расхождение с занятым местом тома. Не называй разницу «системным мусором» без проверки и не обещай освободить весь размер папки.
- Установленные игры, модели, SDK, проекты, офлайн-медиа, история чатов и базы приложений не являются кэшем только из-за размера. Для облачной папки предлагай штатное освобождение локальной копии, когда оно доступно и проверено; обычное удаление может синхронизироваться с облаком.
- Без предыдущего сопоставимого замера не утверждай, когда и из-за чего место исчезло. Время изменения файла само по себе не доказывает рост его размера. Если пользователь спрашивает о росте, сравни доступные прежние замеры при одинаковых путях и единицах.

## Формат результата

Начни с ёмкости, занятого и свободного места. Затем дай короткий список крупнейших непересекающихся категорий по убыванию, обычно 5–10 пунктов. Назови понятное содержимое крупных ветвей, а не только технический путь. Сократи список, если нескольких пунктов достаточно.

После списка назови измеренные кандидаты на очистку и их приблизительный суммарный объём. Это оценка потенциального резерва, а не обещание. Если данных для такой оценки нет, не придумывай её. Подробные команды удаления в диагностический отчёт не включай.

В конце укажи существенные ограничения замера и факт, что ничего не удалялось. Обычный ответ оформляй короткими абзацами и списком, без декоративных заголовков. Реальные пути используй только когда они помогают найти данные.

Пример формы, все числа и пути нужно заменить результатами текущего замера:

```text
Диск заполнен примерно на 98%: занято 484 из 494 ГБ. Свободно около 10 ГБ.

Основные потребители места:

- Данные приложений: 98 ГБ, включая игры, кэши и инструменты разработки.
- Установленные приложения: 54 ГБ.
- Проекты: 49 ГБ.
- Документы: 47 ГБ, преимущественно локальная копия облачного диска.
- Офлайн-музыка: 46 ГБ.
- Данные ИИ-инструмента: 33 ГБ, из них история сессий занимает 22 ГБ.

Кандидаты на очистку: кэш пакетов, кэши приложений и видеоредактора. По замерам они занимают около 52 ГБ; фактическое освобождение может отличаться.

Ничего не удалял. Часть системных папок закрыта для чтения.
```
